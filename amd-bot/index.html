AMD Bot

Who uses @amd-bot on SGLang PRs, how fast it answers, and whether its workflows are running

How to use it

Comment on any sgl-project/sglang PR:

CommandWhat it does
@amd-bot ci-statusChecks all CI on the PR, says whether each failure is caused by the PR, and flags required jobs that were skipped or AMD tests for the changed code that did not run
@amd-bot reviewFull code review of the PR, with the whole codebase as context
@amd-bot review-focus <areas>Review focused on the areas you name
@amd-bot helpReplies with the list of commands
  • @amd-bot has to start its own line. A mention inside a sentence, or in a quote-reply line (starting with >), does nothing.
  • A space works in place of the hyphen: @amd-bot ci status, @amd-bot review focus <areas>.
  • An unknown command (for example @amd-bot ci) gets the help reply.
  • The bot reacts with 🚀 when it picks a command up, usually within a minute, and answers as amd-bot in a new comment.
Only users in the bot's AUTHORIZED_USERS can run commands; other users' commands are ignored.

What the bot publishes
Commands are the @amd-bot comments on sgl-project/sglang PRs, read the way the bot reads them: the trigger has to start an unquoted line, and a bare @amd-bot asks for a review. Each is paired with the first answer of its kind posted after it for the same user (a CI Status for PR, Claude Code Review or help comment), whichever account posted it. A command with no answer is in flight for its first 2 hours and no answer after that; one from a user missing from the bot's AUTHORIZED_USERS is not authorized, because the bot ignores it. Workflow runs are read from the bot repo's Actions.
